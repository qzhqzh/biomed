# 项目决策

日期：2026-10-09，用户时间 Asia/Shanghai。

| 编号 | 决定 | 状态与理由 |
| --- | --- | --- |
| D01 | 先指南、药物、临床试验检索，后医保核查 | 用户已确认 |
| D02 | 先搭可运行框架，边走通边积累经验，不要求照搬参考产品 | 用户已确认 |
| D03 | 项目暂名肿瘤资料工作台，目录 oncology-workbench | 实施命名，后续可改，不绑定对外品牌 |
| D04 | 第一轮仅用教学资料和虚构病例 | 先验证流程，避免把未核实内容当作临床依据 |
| D05 | 首轮文字输入、规则提取；暂不接模型、OCR、语音 | 无凭据或 GPU 依赖，便于定位真实瓶颈 |
| D06 | FastAPI、原生网页、JSON 资料、SQLite 经验库 | 足以支持当前单实例流程，后续有证据再扩展 |
| D07 | PostgreSQL 与可选语义检索为演进方向 | 尚未部署；向量检索不能替代普通条件和来源版本 |
| D08 | 不把诊疗资料和病例自动转为训练材料 | 反馈先成为可审查问题，不自动修改知识库 |

## 启动真实资料迭代前需要补齐

- 谁是首批使用者，先选哪个癌种，最常查询的问题是什么。
- 有哪些可以导入、索引、展示的资料，授权范围和维护责任是什么。
- 是否需要病例持久化；如需要，存储目的、访问边界和保留期限如何规定。
- 是否已有获准使用的院内模型、图片或语音服务。
- 后续医保核查的统筹地区、DRG 或 DIP、实际执行版本、核准对照数据。

这些信息不阻塞合成数据原型。到需要使用它们的阶段再确认，不提前把未确认假设写成已具备的能力。

## 本机环境观察

本次只读检查显示 x86_64、32 个逻辑 CPU、约 94 GiB 内存，Docker、uv、Python 已安装。资源是共享服务器快照，不是本项目的预留配额。NVIDIA 工具无法与驱动通信，未确认可用 GPU，因此第一版不依赖本机模型推理。
