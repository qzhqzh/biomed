# 数据来源方案

当前应用只装载自建教学数据。下表是下一阶段接入候选，不是已获得的数据或授权清单。每个真实来源需要分别确认访问方式、使用权、更新方式和输出范围。

| 类别 | 候选来源 | 首次接入方式 | 必须保留的信息 |
| --- | --- | --- | --- |
| 肿瘤指南 | 医院已合法获取并允许相应用途的指南 | 先确认授权范围，再人工核对小批结构化条目 | 出版方、年份、版次、章节/页码、推荐条件、脚注、权利范围 |
| 药物 | 国家药监局资料、获准使用的说明书及院内药学资料 | 先核对少量批准信息和适应症，不默认存在可批量采集 API | 批准地区、状态、批准日期、说明书版本、适应症原文 |
| 国内临床试验 | 国家药监局药审中心药物临床试验登记与信息公示平台 | 按平台支持方式或获得许可的文件接入，接口可用性待核实 | 登记号、方案、入排原文、总体及中心状态、最后更新和核对时间 |
| 国际临床试验 | ClinicalTrials.gov API v2 | 首选官方 API；在资料同步进程获取公共数据 | NCT 号、适用条件原文、国家和中心、状态、来源修改时间 |
| 医保规则 | 国家医保局及试点统筹地区正式文件 | 后续单独接入 DRG 或 DIP 执行包 | 地区、模式、版本、生效日期、代码、参数来源、核准比对集 |

国内临床试验入口：[药物临床试验登记与信息公示平台](https://www.chinadrugtrials.org.cn/)。药品公开查询入口：[国家药监局政务服务窗口](https://www.nmpa.gov.cn/zwfwqjd/index.html?type=pc)。入口存在不意味着可以不受限制地批量抓取。

ClinicalTrials.gov 官方说明提供 REST API v2，并建议用 API 获取结构化研究资料，而非解析动态网页。接入时从官方 API 定义核对字段和分页，完成一条记录验证后再扩大同步。[NLM API v2 说明](https://www.nlm.nih.gov/pubs/techbull/ma24/ma24_clinicaltrials_api.html)、[NLM 数据获取说明](https://www.nlm.nih.gov/pubs/techbull/ja25/ja25_clinical_trials_screen-scraping.html)

## 来源登记与发布

每个来源登记 source_id、原始地址、获取方式、rights_status、使用范围、负责人；每个版本保存发布/获取时间、文件摘要、解析器版本、审核状态和撤回状态。人工录入也必须追溯到具体原文位置，不把模型生成文本登记成官方原文。

草稿资料与已核对资料隔离。模型可以提出切分、字段或关联候选；发布需要审核记录。新版本保存差异，旧查询关联原版本，授权到期或来源撤回时使相关条目退出检索。公共资料同步与患者查询分开，病例文本和画像不传给外部资料 API。

## 三个不能省略的区别

1. 指南推荐等级、监管批准适应症、医保支付范围是不同事实，各自保留来源。
2. 试验总体处于招募状态，不代表目标城市的研究中心仍在招募；登记信息也可能滞后。
3. 把资料向量化不改变原作品的权利边界；自有编排的权利不能替代原指南的使用授权。[著作权法第十三条与第十五条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

国家医保局 2026-09-02 的说明给出 DRG 3.0 的 492 个核心组、825 个细分组；这不是本项目已有规则库，也不能替代当地执行规则和支付参数。[国家医保局说明](https://www.nhsa.gov.cn/art/2026/9/2/art_14_21978.html)

## 第一批数据的规模

不以条目总数作为完成标准。建议先围绕 5 个真实检索问题整理足够覆盖的小批资料：每条都能打开出处、看懂适用条件、确定更新责任，再评估扩大范围。若指南授权暂时不明确，继续使用教学条目验证流程，并先对接许可明确的公共试验资料。
