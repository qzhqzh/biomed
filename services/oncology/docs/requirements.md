# 需求说明

项目面向肿瘤医生及一起构建工具的研发人员。先让一条检索流程可靠地走通，再通过实际使用决定扩展；参考文章用于识别场景，不构成需要逐项复制的产品清单。

场景参考为用户提供全文的[天界系统介绍文章](https://mp.weixin.qq.com/s/sZcOaxusUXMdAAo50Erfig)。本项目独立实现，不使用对方代码、数据库或未经授权的指南正文。

## 已确认的目标

- 2026-10-09 用户选择：先做肿瘤指南、药物和临床试验检索，再接医保核查。
- 同日进一步明确：不必完全相同，先搭起架子，在走通的过程中找问题、积累经验。
- 本轮交付包含需求方案、可运行代码、验证证据和服务器目录。

## 首条完整流程

虚构病例文字输入 → 提取候选字段 → 人工修改确认 → 查询三类资料 → 查看出处与条件 → 记录问题与经验 → 修改后复测。

每一步都能独立观察。某类资料没有匹配结果，其他结果仍可使用；不为了填满界面编造条目。

## 首期需求及验收

| 编号 | 需求 | 验收行为 |
| --- | --- | --- |
| R01 | 文字输入与有限字段提取 | 示例能识别癌种、分期、分子特征、既往治疗；未识别信息为空 |
| R02 | 医生确认字段 | 未勾选确认不允许查询；修改输入或字段后确认失效，旧结果清空 |
| R03 | 指南条目检索 | 返回当前样例库中条件相关的条目，并展示出处、版本和条件 |
| R04 | 药物资料检索 | 按癌种和分子特征筛选；已用药记录可解释地排除；未用药不等于适用 |
| R05 | 试验资料检索 | 区分字段匹配、待核对和冲突；不显示“已符合入组” |
| R06 | 证据可追溯 | 每个结果能打开原始教学片段和稳定的条目定位 |
| R07 | 诚实的失败状态 | 缺癌种、库中无条目、条件冲突、请求错误分别反馈 |
| R08 | 问题与经验记录 | 填写观察、预期、经验；保存、重启后读取、更新和完整导出 |
| R09 | 教学数据隔离 | 首版只装自建样例；页面和结果有明确标识；病例输入不持久化 |
| R10 | 可运行可验证 | 一条启动路径、健康检查、桌面与手机布局可用、关键路径自动检查 |

## 首期实际范围

提供一个单页工作台、资料目录、问题与经验页面以及对应 API。支持词表中有限的癌种与描述，内置 7 条教学资料覆盖肺腺癌和乳腺癌。这里的“指南”“药物”“试验”是模块类型，数据内容均为教学构造。

先用原生网页和本地服务减少工具链依赖。病例文本不入库；问题记录可能由使用者手动输入敏感内容，因此本版本只开放虚构案例体验，不作为真实病历系统使用。

## 后续能力

真实资料经授权并核对后，逐批导入；接着评估中文术语标准化、结构化筛选与语义检索的效果。只有实际体验表明文字输入成为瓶颈，才增加图片或语音入口。DRG 和 DIP 分别设计，待试点地区、执行版本和基准数据明确后再实现。

当前不做自动诊断、治疗决策、剂量生成、试验报名、自动修改病案、医保申报或收益承诺。不把“有出处”误当作“已适用于当前患者”。

## 产品状态的解释

| 状态 | 对使用者的含义 |
| --- | --- |
| 字段已对应 | 输入与资料中的有限条件一致，仍需阅读原文 |
| 待核对 | 某项未知，或试验入排条件、招募状态尚未核查 |
| 条件不一致 | 当前字段与条目条件冲突，展示原因供检查 |
| 未找到 | 在本次查询的数据范围内没有结果，不代表现实中不存在 |

## 如何判断迭代有效

每轮先收集 5～10 个教学或获准使用的匿名问题，记录期待找到的依据、实际结果和差异。按问题类型统计：提取错误、资料缺失、匹配错误、来源无法追溯、体验不顺。只有观察到明确问题才增加新功能。

首期验收证明软件流程成立，不证明医学准确性。进入真实资料试用前，另由临床人员建立独立核对集，记录样本范围、错误数量、分母和严重程度；不能用“演示成功”替代这项验证。
