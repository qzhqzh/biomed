# 迭代清单

每轮只解决一个能观察的问题，保留输入、预期、实际差异和修复结果。按通过条件推进，不按预设日期承诺上线。

| 阶段 | 要回答的问题 | 交付与通过条件 |
| --- | --- | --- |
| L0 教学流程 | 从病例到依据再到经验，能否完整跑通 | 当前小应用；三类样例检索、出处可读、字段变化使旧结果失效、问题记录可重启恢复 |
| L1 小批真实资料 | 数据从哪里来，能否准确整理并持续维护 | 选择一个癌种，确定授权；人工核对少量资料与真实试验登记，标明数据范围；不得把教学记录当真实数据 |
| L2 检索质量 | 真实提问为什么找不到或找错 | 由临床人员准备核对集；比较精确筛选、术语归一、语义召回，逐条记录遗漏和误匹配 |
| L3 输入效率 | 输入到底卡在哪一步 | 从体验日志决定 OCR、语音或模型提取的优先级；按现有字段契约替换提取器，保留人工确认 |
| L4 受控试用 | 多人使用和敏感数据边界是否落实 | 登录权限、资料审核发布、访问审计、备份恢复、模型数据流核对；完成院内试用准备 |
| L5 医保核查 | 能否复核当地规则并解释差异 | 确定统筹地区、DRG 或 DIP、执行版本、编码与支付参数；用当地核准样本比对；不承诺收入 |

## 下一轮可直接执行的任务

| 任务 | 输入依赖 | 完成证据 |
| --- | --- | --- |
| T01 体验 3 个虚构病例 | 当前工作台 | 至少记录一次提取、一次匹配和一次数据覆盖问题 |
| T02 选定一个首发癌种 | 业务负责人选择；暂以肺腺癌演示 | 明确癌种、主要使用者、最常见的 5 个检索问题 |
| T03 确认可用资料 | 资料持有人和使用范围 | 来源清单、获取方式、可保存/展示/索引的范围 |
| T04 加入首批真实试验快照 | 官方 API 或获准导入文件 | 登记号、原文、更新时间、中心层面状态核对；真实和教学分库 |
| T05 建立人工核对集 | 临床人员参与 | 逐题期待条目及理由、实际结果和错误分类 |
| T06 决定下一项改动 | 上述差异记录 | 选择证据最充分的一项，不同时堆叠所有能力 |

## 一次体验的记录格式

场景 ID：使用虚构场景编号；问题：想查什么；预期：应找到哪些资料或应提示哪些未知；实际：观察到的界面与结果；原因：已验证的原因或待核实假设；改动：最小修复；复测：同场景结果与仍有的限制。

系统内“问题与经验”保存具体记录，docs/lessons.md 保存对后续工程有复用价值的结论。用户反馈尚未收到时，不把技术自测写成“医生认可”或“临床验证通过”。
