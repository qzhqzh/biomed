## 以目标可用产出为验收标准（2026-11-06）

用户明确：符合tumor_api知识库要求才算能用。本阶段的可用产出是满足冻结目标接口、来源与实体映射约束的离线兼容知识；未同步实体、待映射、目标不适用、结构合格或仅存入biomed均单独列出。目标生产仍只读、不导入，不能把离线通过称为已在生产验证。独立语义核读继续暴露错实体、错关系与必要条件丢失，不变成人工必审或提取流程中的重复模型核验。

前三个完成批次的基线为95条记录、72条结构合格、0条目标离线通过；72条中63条超出当前目标入口范围，9条待处理，另23条有提取结构缺口。此处不包括独立开发回归中已经通过的2条KRAS G12C知识；它们只能作为阳性对照，不能再次计为新增收益。

本次已查明两个系统性问题：

- 来源优先级只看标题是否包含trial/treatment/therapy等词，麻醉和护理试验排在前面，`Sotorasib for Lung Cancers with KRAS p.G12C Mutation`反而没有优先分。这不是面向目标证据中心的选文规则。
- 目标支持mutation、cnv、fusion，以及治疗、诊断、预后等类别；当前自动`_scopes`主要只放行单氨基酸变异、单药、单癌种的`treatment_outcome`。当前自动适配覆盖不足，不能将尚未实现的类型统称为目标不支持。真实条件仍不能被删掉来凑通过率。

只读盘点了队列对应的97篇已解析全文，57篇未领取来源中20篇命中基因和事件词共现。**20篇是待判定线索，不是20篇可用文献**：实际包含图号S3A、实验构建体Q63L及背景引用等假阳性，不能直接据此重排为合格输入。盘点结果和原文段落保存在`/appdata/02_resource/apps/biomed/research/artifacts/target-utilization-20261106/source-opportunities.json`；未新增模型调用、下载或目标查询。

待实施优化按以下顺序验收，不把方案描述成已经提效：

1. **目标导向选文和片段筛选**：复用现有4B分类环节，同时识别是否存在明确基因组事件及其治疗、诊断或预后关系；规则提供候选，模型判断关系，疑难保留。区分病人变异、实验构建体、蛋白表达、病理条件和背景提及。泛肿瘤资料保留，但不作为本阶段目标产出；需要补来源时定向补合法全文，沿用既有限速。
2. **按目标字段提取核心关系**：保持9B实体＋Bonsai关系，不新增通用复核模型。事实必须分开癌种、分子条件、临床病理条件、实际干预/对照/支持用药、目标类别、结论及文章/段落出处；一个队列的结果不能绑定到邻近出现的另一药物。正常支持治疗或手术不能混入抗肿瘤药物身份。
3. **补自动适配覆盖**：依据有真实失败例子的类型逐项补CNV、融合、常见缺失/插入、诊断/预后关系及必要的组合条件；用原文和冻结目标契约验证，不把蛋白高表达变成DNA扩增，不猜融合伙伴，不把多条件压成单条件。新实体继续生成自动查重/新增依赖，未回填目标ID时与现成兼容数分开。
4. **跨段合并同一核心知识**：先合并同文献、同人群、同必要条件、同方案和同结论的重复记录，并汇集出处。保留不同队列、比较方向、阳性/阴性结果和时间条件，不能只按癌种＋药物去重。

主指标为新增独立目标兼容知识数、每篇投入来源的可用产出、每GPU小时的可用产出；结构通过率及原文核读错误单列。当前页面的累计记录数仍是原有统计，尚未改成去重后的可用指标。固定真实输入比较旧、新输出及耗时，已通过阳性对照不计新增，反例不能错误放行，不提前承诺通过率。先用小批次证明有新增可用知识且核心错误没有增加，再接入连续处理；先不换模型、不微调。

## 实施与验收方案

1. 独立宿主机服务复用现有GPU运行环境和脚本；长任务不进入资料worker的10分钟执行窗口。调度账本和日志放appdata，生产资料库仅用短只读查询发现来源，写入知识沿用已验证的导入命令。
2. 每篇按来源版本、内容及流水线方法去重；任务领取、批次绑定和重试时间持久化。同一批次重启复用模型断点。已有研究知识单列为历史已处理，不冒充本服务产出。
3. 每批5篇，全量处理入选片段，不设每日篇数与运行时长上限，单GPU串行。无可用文献或资源繁忙时等待，资源空闲后自动继续，保持现有采集限速与全文预算。
4. 临时进程错误等待后有限重试；坏片段保留失败原因，其他片段继续。批次耗尽重试后隔离，其他批次继续；连续系统故障暂停并邮件通知。进程停止终止本服务子进程，重启从同一目录续跑，不清理模型或资料。
5. 工作流页面显示心跳、当前阶段、处理量、结构状态、目标兼容、预算、失败原因与知识入口。每批保存统计、固定抽查样本和简短经验记录；结构合格不标为医学正确，未核验样本明确保留未核验。
6. 验收覆盖自动选样、跨批去重、中断恢复、失败隔离、预算与GPU等待；真实运行两批，核对导入回执、可检索知识、文章/段落出处及原采集配置。服务持续驻留，不依赖聊天进程。

第一版只消费已有全文，不擅自扩大全文下载。自动全文供给可随后沿用采集队列接入。个别名称、PubTator补充收益和模型重新选型不作为本轮前置条件。

## 运行说明

### 固定处理链

| 环节 | 执行者 | 产物与异常处理 |
| --- | --- | --- |
| 领取全文、冻结来源 | 脚本 | 保存PMID、版本、内容摘要、许可及段落；身份不符拒绝替换 |
| 三分类 | Qwen3.5-4B | 实体瘤／血液肿瘤／非肿瘤；排除与输出失败分开记录 |
| 段落筛选、实体抽取 | Qwen3.5-9B | 逐段输出、精确原文定位；坏片段保留原因，其余继续 |
| 关系及必要条件 | Bonsai | 只使用上一步片段与实体；断点复用，不补造答案 |
| 归一与入库 | 字典、规则，歧义调用既定模型 | 本地规则、知识、两层出处及入库回执；重复交付幂等 |
| 目标结构与独立评估 | 脚本、另行原文核读 | 离线兼容包、固定样本和经验；不写目标生产、不阻断知识保存 |

PubTator只为进入提取的文献获取并缓存标注，沿用现有限速；本地模型全部照常运行。PubTator不可用独立记录。

新安装在启动知识 worker 前，运行 `.venv/bin/python scripts/install_runtime_definitions.py`，将仓库中的三分类和实体抽取提示词初始化到既有运行位置。工具校验固定版本哈希，不覆盖已有文件；当前服务器已具备这些定义，无需重复迁移。基因参考库、模型权重和文献仍按部署说明单独配置。

### 持续运行和恢复

- 用户systemd服务`biomed-knowledge-worker.service`开机驻留、异常退出后60秒重启；用户linger已开启，不依赖终端或聊天。
- 每批5篇，`daily_articles`与`daily_runtime_seconds`默认及现用值均为JSON `null`，表示不限；仍按UTC自然日记录新领取篇数和实际任务时长。时间包括来源准备、冷加载、推理及交付，等待资源不计入；恢复不重复计篇数，跨日继续未完成批次。兼容显式正整数上限，两项可单独设置；0不是不限。
- 固定GPU 3，启动前要求空闲显存至少21GiB、主机可用内存至少16GiB，60秒平均磁盘完全阻塞低于20%、内存压力低于2%；进程降低CPU／I/O优先级。该检查是启动前避让，不保证加载期间毫无资源竞争。
- `/data`和`/appdata`分别保留至少10GiB及4096个空闲inode。无来源或资源不足时在线等待；PubTator遇429等临时错误沿用持久退避，不为解除每日上限而加速请求。
- 批次进程最多尝试3次，重试前分别等60、300秒；耗尽后隔离，继续其他批次。连续3批耗尽重试则暂停并邮件通知。用户暂停、重启及预算中断不消耗错误重试额度。
- 当前阶段连续30分钟没有新结果或状态变化时，只终止本服务子进程并进入上述有限重试，避免挂起任务持续占用资源。
- 来源发现按段落版本索引及主键读取，短锁等待、每条查询3秒预算；来源暂时锁库不阻断已有冻结批次。网页读取状态文件，不为进度查询百万级资料库。
- 复用现有Claw邮箱，向`已配置的收件邮箱`通知首10篇尝试结果、当前队列处理完毕、连续系统故障及持续环境错误。SMTP失败保存待发消息，空闲时也按退避重试，不依赖下个批次完成；服务器接受不等于收件箱已收到。

### 评估与经验复用

每批自动统计文章去向、保存记录、结构合格、目标缺口、重复问题和运行耗时。保存记录可能包含失败占位，不能当成有效知识数；独立核读也不是提取或检索的门槛。

核读评价实际保留的核心癌种、药物、关系、必要条件与出处。未保留的非必要细节不要求逐字重现；改变知识含义的错实体、错关系、条件丢失、错引必须记录。固定小样本分别报告支持／不支持／未确定，不声称全批准确率。

核读JSON需有`source_run`、`sample_sha256`、实际`reviewer`及逐条`group_id`、`decision`、`reason`、`evidence_quotes`、`issue_codes`，可加最多3条`lessons`。摘要用`apps.curation.knowledge_processing.identity`计算，引用须来自固定原文锚点。无锚点只能判不支持或未确定，并标记`missing_source_anchor`。

```bash
.venv/bin/python -B scripts/knowledge_worker.py evaluate \
  --batch <已完成批次ID> --input <实际核读结果.json>
```

核读结果在工作流显示，不改原样本、事实、历史核读或发布状态。首版不会伪造自动评分，也不让模型自行改提示词。后续只选影响产出的重复问题，每次改变一个因素，用冻结样本比较后决定保留；实体确认沿用本地库，不逐篇重复审核。

目标适配另按`biomed.target-readiness.v1`汇总：结构缺口不混入适配分母；目标不能表达、真正待处理、等待自动新增实体和离线通过分别显示。名称匹配不能解决目标缺少表达量／机制入口的问题。已有批次可以只更新派生统计，不重跑模型，不覆盖原导出、知识或核读：

```bash
.venv/bin/python -B scripts/knowledge_worker.py reassess-target --batch <已完成批次ID>
```

派生诊断追加保存在同批`target-readiness/`，与原入库文件摘要绑定。知识页面使用相同规则解释原适配状态，数据库事实及审核记录保持不变。具体例子、目标源码约束和成功对照见[适配原因核对](tumor-api-export.md#常驻首批为何29条结构合格目标通过为02026-11-06)。
