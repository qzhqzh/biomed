# 工程经验

## 常驻知识处理（2026-11-06）

复用批次提取脚本时，模型断点之外仍需持久记录任务领取、每日预算、重试时间、逐篇去向和真实入库回执。服务重启应续用原批次；坏片段、分类排除、结构合格和语义正确分别计数。账本或状态写入失败时也要清理本服务模型子进程，不能留下失去监督的GPU任务。

已有全文发现改从小型段落版本索引出发，每条只读查询有短锁等待与执行预算；来源锁库不应阻断已冻结批次续跑。工作流新增状态来自原子文件，旧运行状态使用轻量接口，资料任务列表按需加载，避免查看知识进度时再次触发全库统计。

实测中web重建遇到共享containerd清理超时，等待原清理完成后恢复本项目web，未重启共享Docker。静态资源仍按宿主机构建、collectstatic、web HUP的顺序更新。常驻调度检查主机内存／I/O压力，并保留原模型与资料路径；服务在线、模型在算、入库成功及核验正确须各用实际证据确认。

## 模型资源与断点下载（2026-10-22）

## 本体分类入口不能只找无父节点（2026-10-24）

MONDO 的 disease 等入口有 BFO 外部父级。如果仅将 parents 为空的概念当入口，真实疾病分支会从浏览页面消失。应按当前 release 内有无父级定义本库入口，同时保留并显示外部父ID；多父级不得压成单一路径。分类数据按 release 缓存和固定查询，前端只读取当前层级。OncoTree 的 flat API 不含真实 TISSUE 根，完整树 API 则包含，统计必须区分癌种、组织分组和根节点。

## 外部资源的中文和机制条件（2026-10-25）

中文来源可能使用`zh`、`zh-hans`、`zh-cn`、`zh-hant`等标签；只接收`zh-Hans`会静默丢失有效数据，应保留原语言并按中文语言族处理。语言标为中文也可能只有拉丁名或研发代码，不能计入中文覆盖。标准ID与英文别名精确匹配只能证明候选关联，不能证明来源中文语义正确：本轮发现PNET译为另一类肿瘤、LPL译为巨球蛋白血症，以及药物标签使用品牌。原始参考与显示层分开保存，排除理由可查；项目补充译名明确标记草稿，不伪装官方名称。

ChEMBL机制展示不能压成没有条件的“药物—靶点”。action_type、直接/间接作用、细胞/分子机制标记、选择性和comment、原始参考必须随记录保留；总体开发阶段不能替代每个适应症的阶段。名称候选、盐型/母体关系和正式已审核临床证据分别建模，缺失字段不自动补结论。

## 采集恢复要区分传输状态与正文错误（2026-10-28）

PubMed ESearch实际出现HTTP 200正文内嵌`Search Backend failed / Status: 500`，原计数校验误判为永久异常。按已归档响应，只将明确后端500/502/503/504接入既有有限退避；未知、查询错误与缺失计数继续暂停，不能把所有异常都当临时错误或空结果。59项采集/恢复测试通过，正式恢复后原分片游标继续推进，限速、预算及旧数据保持。

百万级库排障应优先按主键读取批次状态或当前分片游标；完整分类统计可能长时间持有读锁，在SQLite DELETE模式下阻碍写事务提交。`?summary=1`并不保证查询轻量，见下方2026-11-01记录。命令宿主侧超时后应核验容器内子进程是否结束；本次长读结束后正常恢复，无需盲目重启或临时切换数据库日志模式。游标推进包含去重，不能据此虚报新增文献数量。

## 百万级文献库的只读查询也会阻塞采集（2026-11-01）

本轮选样使用`MaterialVersion.annotate(Count("passages")).order_by("acquired_at")[:70]`；LIMIT并未限制此前的关联聚合和排序，容器内查询持续运行数分钟。随后检查发现`collections/?summary=1`只省略分类统计，`collection_data`仍对整批entries做GROUP BY、对fetches做聚合；因此不能把它当作小表健康探针。HTTP客户端超时也不会自动中止服务器SQL。

实际内核锁显示web读请求持SHARED锁、采集worker持PENDING/RESERVED锁等待；新只读连接查询知识小表也返回`database is locked`，而`/health/ready`仍快速返回200。健康页正常不能证明采集库可读写。此次只精确结束自建ORM查询及已确认持锁的web子进程，让gunicorn补进程；未停止采集worker、操作journal、迁移数据库或切换日志模式。

## 转录本外显子数不能直接等同参考映射块数（2026-10-28）

本地`hg19_refGeneWithVer.txt`和`hg38_refGeneWithVer.txt`中，`NM_000348.4`（SRD5A2）的`exonCount`分别为6和5。在线核验发现，[NCBI精确版本GenBank记录](https://www.ncbi.nlm.nih.gov/nuccore/NM_000348.4?report=genbank)明确列出5个exon：转录本坐标1–319、320–483、484–585、586–736、737–4519（1-based闭区间）。

[UCSC hg19官方PSL](https://api.genome.ucsc.edu/getData/track?genome=hg19;track=ncbiRefSeqPsl;chrom=chr2;start=31747549;end=31806007)的同版本记录有6块，但`qNumInsert=1/qBaseInsert=1`；末两块长191、127，转录本起点4200、4392，基因组起点31805689、31805880。因此转录本间隔1 bp、基因组间隔0 bp，是一个外显子被比对拆块。[hg38对应PSL](https://api.genome.ucsc.edu/getData/track?genome=hg38;track=ncbiRefSeqPsl;chrom=chr2;start=31522479;end=31580938)为5块、无转录本插入，对应块长319。NCBI的基因组注释还可能用人工微内含子恢复读框，见[官方格式说明](https://www.ncbi.nlm.nih.gov/datasets/docs/v2/reference-docs/file-formats/annotation-files/about-ncbi-gff3/#annotation-accommodations-for-putative-assembly-errors)。不能把这类拆分解释为新增生物学外显子。

此转录本外显子总数应记5，原映射计数6及其组装/来源另行保留。批量注释应优先完整转录本版本的exon特征；参考映射块数只作候选，异常需核验，不以短间隔阈值一律合并。本地两库共同76,482个版本ID中98.24%计数唯一且一致，仅为映射表一致率，不能当作外显子注释准确率；其余差异未逐条查因。本次未改参考库，也未对尚未提供的用户表格执行注释。

## 磁盘同步写与空闲心跳（2026-11-14）

在当时的共享磁盘压力下，采集 worker 每约 10 秒的空闲心跳持有 SQLite 排他锁约 3.7–4.1 秒。独立临时数据库的三次写入，在 `/appdata` 上提交中位数为约 2.38 秒，并有读请求遇到 busy；该小样本仅说明当时的同步写代价，不代表长期基准。模型读取、数据库及 `/appdata` 镜像共用 `/data` 后端，不能把模型加载时间全部归因于磁盘本身：部分实验还主动限速。

代码已减少空闲心跳数据库写入和可重建状态文件的同步写。原资料 worker 经临时恢复后已切回并健康运行：35 秒抽样期间 33 次主键读取成功，未观察到此前的周期性排他锁。采样不能证明其他写入或高并发场景不会竞争；知识处理状态减写待服务下一次正常启动后生效。Web 健康检查为 200 不代表资料 worker 正常。部署、回滚和当前状态见 [部署说明](DEPLOY.md#空闲心跳和状态文件减写2026-11-14)。

恢复后的另一次 12 秒采样中，当前分类模型进程从本地存储读取约 25.6 MiB/s；共享虚拟磁盘仍有明显 I/O 等待。最近三个完成批次各分类 5 篇，4B 分类模型的加载分别为 205.2、156.8、223.7 秒，实际推理分别为 5.5、5.1、5.0 秒；其他初始化与保存时间不计入推理。每批重新加载模型是下一处可验证的优化点，但需保留逐篇来源、结果和断点，并核对其他阶段的显存占用，不能仅按加载时间推断整体提速或知识产出。
