## 保存结构

- `apps/curation/research_data/*.json`：本机完整研究档案，可能包含文献原文片段，不提交到公开仓库。原文件及其哈希保持不变。
- `apps/curation/research_public_data/*.json`：随代码保存的方法、指标、分类结果和来源哈希摘要，不包含完整档案中的原文片段。读取同一研究时优先使用本机完整档案；缺失时使用仓库摘要。
- `var/experiments/`：原始快照、逐篇推理、参考与评测，保留不覆盖，不由网页提供任意文件下载。
- `apps/curation/research_history.py`：固定目录只读查询与追加登记；`research_views.py` 提供 GET API。沿用现有 apps 只读挂载，无新数据库表或服务。
- `scripts/export_research_history.py`：从实际评测和历史文档导出原有档案；病例字段使用白名单。`scripts/evaluate_model_comparison.py` 登记五模型对照及其分类原始输出，不公开主机绝对路径或私有配置。
- `scripts/export_public_research_history.py`：按字段白名单生成公开摘要；已有摘要不可覆盖，研究结果变更需登记新的版本。

每条档案保存任务版本、样本版本、方法版本、参考版本及来源文件哈希。`fingerprint` 标识实验条件；`content_sha256` 校验档案内容。历史文档重建的记录标为 `documented_only`，不能冒称完整冻结了旧环境；新的三分类对照基于实际冻结样本和方法。

公开API将来源文件的绝对路径转成项目内相对路径，项目外仅显示文件名；源档案不改写，来源文件哈希及实验身份保留。返回的`content_sha256`对应公开投影。没有实际入库回执的研究记录不生成候选库链接。

025的完整核对投影约4.01 MiB，包含210条记录和可追溯原文；档案单文件上限调整为8 MiB，页面每次渲染20条，避免同时展开全部卡片。该调整不放宽来源、入库回执或历史不可覆盖检查。

## 后续先查再试

```bash
# 列出已登记实验。
.venv/bin/python scripts/research_history.py list

# 新试验前，以准备使用的 identity 查是否已有相同条件。
# 输入可以是只有 identity 的 JSON，或完整研究档案。
.venv/bin/python scripts/research_history.py check path/to/proposed-record.json

# 结果检查后追加登记；同 ID 同内容会复用，不重复写入。
.venv/bin/python scripts/research_history.py register path/to/new-record.json

# 重建当前这批安全投影；已有相同档案只返回 reused，不重跑模型。
.venv/bin/python scripts/export_research_history.py
```

这是研究前的条件查询和记录机制，不是自动禁止所有模型进程重跑的全局锁。已有推理脚本自身也保存输入/配置哈希、逐篇结果和断点，原实验继续由原脚本按其协议复用。

同一 ID 的不同内容会被拒绝；更新结论或参考必须使用新 ID 保存修订，不能覆盖原档案。相同实验条件可以有不同记录版本，条件查询会一并列出。导出脚本如果发现来源文档变化，会触发冲突，不能强制覆盖以追求“导出成功”。
