## 速度、预算与恢复

| 控制 | 默认值 | 行为 |
| --- | --- | --- |
| 文献名额 | 50 篇 | 已发现的待下载 PMID 也占名额；不能下调到已发现数量以下 |
| 全文尝试 | 5 篇 | 无权获取 / 不能解析也计入；传输重试另计请求预算 |
| 并发 | 1 | 现有资料 worker 单实例，全库同时只允许一个活动采集批次 |
| 请求间隔 | 2 秒 | 在不同批次的最近请求之间也保留间隔；默认低于官方 3 次/秒上限 |
| 读取速度 | 256 KiB/s，约 2.1 Mbit/s | 应用读取平均上限；不是整台设备的网络整形，TCP 缓冲仍可能短暂突发 |
| 累计响应预算 | 100 MiB | 每个请求按压缩体与解压体的较大值扣减；不含 HTTP/TLS 开销 |
| 请求次数 | 100 次 | 包括计数、ID 清单、元数据、全文及失败尝试 |
| 单响应限制 | 计数 / ID 1 MiB，元数据 8 MiB，全文 25 MiB | 同时受剩余批次预算约束；读取过程也有时限 |
| 磁盘余量 | 至少 1 GiB | 低于阈值暂停；响应预算不是 SQLite、原始快照及解析文本合计磁盘硬配额 |

读取前持久预留响应预算，结束后以实际大小结算；进程异常退出时预留量继续计入，防止重试突破预算。账本中的 `wire_bytes` 是已完成记账的 HTTP 响应体字节，异常中断时可能低于真实传输；`charged_bytes` 保留保守预留额。原始批量响应、拆出的单篇快照、分类输入及解析段落均会占空间，实际磁盘增长须另测。

暂停阻止后续请求，允许当前单次响应结束并保存断点。处理中不能改预算；已暂停时提高**累计**上限续跑，不会重置已用流量和请求次数。队列租约恢复、步骤编号及数据库唯一约束防止重复推进。临时错误按 60 / 300 / 900 / 1800 / 3600 秒等待，连续 6 次失败暂停；来源要求更久时遵守 Retry-After，手动暂停后续跑也不能绕过已有冷却时间。成功提交断点后清零连续失败计数，没有自动换 IP 或提高并发。详情见[恢复与通知](#recovery-and-notifications)。
