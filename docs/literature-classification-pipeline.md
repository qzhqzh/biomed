## 拆成八个可独立检查的环节

这是目标流程，不表示已部署八个模型或八套分类任务。现有规则结果继续作为基线。

| 环节 | 要回答的问题与输出 | 建议执行方式 | 当前基础与缺口 |
| --- | --- | --- | --- |
| 1. 资料可用性 | 语言、标题 / 摘要 / 全文是否具备，解析是否成功，来源与版本能否对应 | 读取资料、版本和解析状态；不需要模型猜测 | 已有版本、全文与解析状态；需统一显示完整性及下一步需要什么资料 |
| 2. 发表与来源状态 | 原论文、通知、方案等记录性质；撤稿、更正、关注声明及关联对象 | 来源结构化字段优先，标题补充；冲突独立保留 | 已有规则与冲突线索；需补齐通知和原论文的关系及更新时间 |
| 3. 肿瘤相关性与提及角色 | 实体、血液、混合、良性 / 癌前、泛癌未细分、非肿瘤、资料不足；疾病是主要对象、对照、背景、既往史、偶然合并症还是假设 / 否定 | 规则提供候选；小型指令模型读取上下文并给出依据原句；不确定时保留待判定 | 现有范围规则已覆盖全批，但难以识别文章实际对象；这是优先新增的语义判断 |
| 4. 癌种与组织学 | 器官部位、组织学、多癌种、泛癌及原发灶不明；区分原发与转移部位、正常对照组织 | 词表 / MeSH 候选加上下文关系确认；能映射时连接标准实体 | 已有部位、组织学弱标签；需避免把肝转移的肝误作原发癌种，以及把器官词直接认定为癌种 |
| 5. 研究对象与人群 | 人体、动物、细胞、类器官、混合、未知；年龄人群另设标签 | 结构化字段与分类模型共同提供候选；细胞系名称使用可追溯映射 | 已有 human / preclinical / pediatric 粗标签；需细分研究对象并判断其是否实际参与研究 |
| 6. 研究设计与文章类型 | 原始研究、综述、Meta 分析、病例、方法、方案、评论；原始研究进一步标注随机 / 其他干预 / 观察性 / 实验研究 | 出版类型优先提供线索，摘要补充；允许设计未知或多部分研究 | 已有部分词表；需区分真正采用某设计与背景引用该设计，不据此自动生成证据等级 |
| 7. 研究主题与用途 | 治疗、诊断 / 筛查、预后、标志物、机制、流行病学、预防、支持照护等多标签 | 可与环节 4–6 合并一次模型推理；每个轴单独输出证据及未知状态 | 已有治疗、诊断、生物标志物等规则；需要主题边界和逐轴评测 |
| 8. 后续处理分流 | 可继续摘要分类、适合全文核读 / 抽取、缺全文、缺许可信息、来源冲突、等待模型配置等 | 综合前面各环节与真实资源状态生成任务候选 | 尚无完整分流策略；分类标签不能直接变成已发布临床证据，也不能启动未授权的下载或训练 |

第 1、2 环节使用现有数据即可先执行；第 3 环节确定研究对象及范围，第 4–7 环节可合并读取输入并分别保存结果，第 8 环节汇总。每个环节都允许独立失败、未知或有冲突；缺组织学标签不会阻止保存可靠的研究类型标签。肿瘤相关性、发表状态、资料完整性和人工抽查状态相互独立。

相关性先扩充独立的细分理由，保留当前 `scope` 枚举的兼容映射。例如，泛癌未细分、非肿瘤与信息不足暂时仍映射为旧接口 `uncertain`，由新字段说明差异；不直接改旧词表或覆写历史结果。确认是范围外的文献也保留元数据和依据，不自动删除。

## 模型分工与调用成本

- 现有规则负责可追溯的快速候选及来源状态。模型不能用语义猜测覆盖来源明确的撤稿记录；来源冲突进入专门核对队列。
- 首轮候选为 [GLiNER2](https://huggingface.co/fastino/gliner2-base-v1) 与 [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)：前者支持分类和结构化抽取，可用于多轴标签对照；后者用于按明确标签规范阅读上下文。是否能改善肿瘤分类必须由本批评测验证。
- 多环节不等于多次模型调用。对同一标题 / 摘要，一次固定结构的输出可覆盖第 3–7 环节；各字段仍有各自依据和未知状态。初期对照在固定样本上同时测各方法，避免只测规则已经拒判的条目。
- 验证后再考虑按需调用：规则与轻量模型先给候选，信息不足、方法分歧及抽样质检条目进入小型指令模型。抽样检查已判定条目，避免漏掉规则自信但错误的情况。置信阈值须由验证集确定，模型自报分数不能直接视为校准概率。
- 标注与独立评测稳定后，再评估 [BiomedBERT](https://huggingface.co/microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract) 的任务微调用于批量分类。原始模型是预训练编码器，需要分类头及任务数据，当前不启动训练。
- 实验从本地已有标题 / 摘要开始，全文只在必要时使用已取得的 49 篇；不自动补下载。记录实际输入 / 输出量、每篇耗时、批量吞吐和显存占用，分别报告首次加载与预热后性能，不提前承诺每千篇耗时。

## 每个环节保存与展示的内容

复用现有资料版本、`LiteratureClassification` 与工作队列，后续实现时以新执行记录和结果版本追加，不覆盖 v1–v3 或本轮核读标签。设计至少需要以下字段；此处不宣布数据库或 API 已完成变更：

- 输入：资料版本 ID、内容哈希、实际使用的标题 / 摘要 / 全文段落及范围；全文不可得时明确记录实际使用元数据。
- 方法：环节 ID、标签规范版本、规则或模型版本、提示词版本、运行配置和时间。
- 结果：各轴标签、`candidate / unknown / conflict` 判断状态、理由、原文证据及字段 / 字符偏移；原文不支持的字段保持未知，不能由背景知识补齐。
- 执行状态：未执行、执行中、完成、失败，以及没有真实模型时的 `waiting_configuration`；执行完成不等于判定正确。
- 核对：自动结果、助手暂定参考、人工抽查分别存档，保存标注身份和修订历史；不能混为一个“已审核”数字。

进度应分别展示“已处理篇数 / 有候选标签篇数 / 待判定篇数 / 已核读篇数”，逐轴报告覆盖率和错误率。分类形成的处理优先级不替代正式证据的抽取与独立 AI 审核；仍遵循 **AI 通过即可发布、人工抽查独立** 的既有产品规则，不增设全量人工必审。

## 下一步顺序与检查方法

1. **先把标注规范拆到各轴**：用已有 100 篇核读材料和 12 篇范围分歧、2 条发表状态冲突说明边界；不把当前弱标签直接作为答案。优先解决研究对象 / 背景提及和待判定理由。
2. **从现有 1,000 篇中固定新的保留样本**：既包括待判定，也包括已判定实体、血液、边界及不同研究类型；按关联论文分组。本轮已打开的 40 篇保留集若参与设计或调优，则成为后续开发材料；原历史分数仍保留。新保留样本的标签不用于提示词或规则调整。
3. **再做有上限的离线推理对照**：建议首轮限定 100 篇开发样本、两种候选模型，对照现有 v3；这是下一步实验建议，尚未执行。参考标签需明确人工复核程度；没有独立参考的轴只报告候选和覆盖，不编造准确率。模型 / 提示词冻结后才评估新保留样本。
4. **按环节决定是否接入**：相关性看每类精确率 / 召回率、漏检和拒判量；多标签轴看逐类和 macro-F1；提及角色、原发 / 转移关系及出处支持单独核对。报告分母与少样本限制；不同环节可分别保留规则或采用模型。
5. **最后决定扩大采集或训练**：当前只有单批近期文献，不能声称覆盖五年分布。先完成质量、吞吐与资源评估，维持现有限速及暂停状态；训练和扩大采集仍按后续安排执行。

本次变更仅为方案和统计记录，不改变线上任务、数据库结构、分类结果或服务部署。现有实测与核读文件见[分类评测记录](literature-evaluation.md)，采集状态与原文路径见[采集说明](literature-collection.md)。
