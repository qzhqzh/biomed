### 提取与核验分开：按目标知识结构评价（2026-11-01用户明确）

**提取主流程：原文 → 文献/段落筛选 → 实体和关系抽取 → biomed知识库 → tumor_api目标格式适配。语义核验是独立的后续质量评价，不作为提取、保存知识或生成兼容包的必经模型步骤。** 每条知识可以先处于未核验状态；以后核验绑定该知识版本、原文版本和标准版本，保存有效/无效/待判定、具体问题及依据，不改写原记录。Astra或其他核验模型的选择不阻塞提取主流程，不增加固定二次模型调用。

目标是抽取业务需要的知识，不是完整重建论文全部信息。先按目标知识类型列出必需字段、可选字段和不采字段，再据此评实体与关系。目标不要求的样本量、数值、置信区间或完整研究叙述没有结构化，不单独判提取无效；原文及文章/段落两层出处继续保留。若缺失信息改变了实际保存的关系，例如联合变单药、否定变肯定或分子限定消失，则归入实体/关系错误，不属于允许的信息压缩。

示意原文为“A+B联合治疗X癌，20例中12例有效”：若目标知识仅要求药物、癌种及关系，则正确保存“A+B联合—X癌—文献报告治疗获益”可判有效，未存12/20不扣分；若存成“A单药—X癌—获益”或药物/癌种身份错，则判无效。若目标另要求有效率，12/20才进入该版本必需字段的评分。

### 当前业务收录粒度：主癌种优先（2026-10-29用户补充）

当前阶段的目标是先把文献转换成可检索、可关联的知识条目；不能把后续精细核验全部提前作为收录门槛。疾病库可以保留细分层级，但知识关联、检索和统计使用业务主癌种。用户已明确：**转移性乳腺癌关联到乳腺癌即可**；“转移性”及其他分期细节随原文保存，后续再核对，不要求在这一阶段单独建词条、规范成字段或核验通过。

本阶段优先保留主癌种、核心实体、原文支持的关系/结论，以及文章和原文片段两层出处。细分描述未结构化不能单独判定整条失败。模型原文、来源范围和已有下级词条仍保留，不合并删除标准库节点；主癌种归类与证据范围核验是不同工作。其他癌种的业务主级别有歧义时再提出具体选项，不凭“乳腺癌”一例任意合并所有分子/组织学类别。

**药物粒度也已由用户明确：必须保留原文明示的具体药名或联合方案，才能用于知识库与报告。** “免疫治疗”“化疗”等只作分类标签，不能替代已有具体药物。联合、序贯、既往用药和当前治疗分别保留，不因同篇出现两个药就组成联合方案。若当前片段未列出完整成分，保留已有药名并标明缺口，后续从原文补充，不凭常识猜测。

**药名按原文字面提取，不主动缩写或转换名称。** 本轮示例必须保留`ipilimumab`、`nivolumab`、`durvalumab`及原文明确的联合关系，不能换成缩写、译名、其他别名或治疗类别。方案原文与成员药名分别保留，成员药名可逐字定位。标准词条ID及别名关联单独存放，不覆盖原文药名；原文本身只有缩写时保留原缩写与出处，不凭模型记忆扩写。这个约定用于后续抽取与检查，不覆盖011已冻结的原始输出或成绩。

011的严格事实核验结果保持冻结，作为诊断材料，**不直接充当当前知识收录门槛**。012已按同一新业务口径重评旧输出，再比较新输出，不把口径放宽称为模型能力提升。011中K07把ipilimumab+nivolumab省成immune checkpoint blockade，K08/K09把durvalumab省成combined chemoimmunotherapy，属于核心药物信息遗漏；012均已补回。未进行生产入库。

**大小写是名称关联流程负责的可确定问题，不是知识内容错误。** 完整药名忽略大小写查找已有药物实体及原文，确认同一身份后保存原文拼写和位置，另外保留模型原词；不调用消歧模型。012的`dexamethasone`已对应原文`Dexamethasone`恢复可用。该规则不扩写缩写、不替换别名，也不沿用到存在冲突的基因符号等词条。

## 1. 目标与项目边界

首个产品场景是知识库维护：指定资料 → 提取有出处的独立证据 → 与已有知识比较 → 保存可检索知识 → 生成目标格式的导出预览。报告解读和生产接入在后续阶段。

- biomed 是独立项目。`tumor_api`、`tumor_html` 及其公共组件仅作只读结构参考；不修改它们的代码、数据库、服务、权限或运行配置，不调用写接口。
- 结构设计以覆盖目标知识库语义为长期要求；首批重点验证治疗证据。支持一个类型枚举不等于已经实现或验证该类型的抽取。
- 沿用已有资料、版本、原文定位、工作流和证据机制；仅执行有预算的离线开发试验，不运行迁移、训练、全量推理或额外下载，不改采集限速。
- biomed 仍是 AI 核验通过即可发布、人工抽查独立。试验输出与正式证据分开；评测需要参考标注，不等于线上每条证据必须人工审批。
- 未配置模型时保持 `waiting_configuration`，不能用规则输出或助手示例冒充已完成的模型抽取。

## 2. 对原方案的评价

“文献筛选 → 证据句筛选 → 实体识别和类型判定”的思路适合拆解任务、降低调用成本、定位错误，但尚缺关系、条件、研究语境和来源核验。

1. **早期硬排除会造成不可恢复的漏检。** 分类先用于路由和优先级，保留未知、混合、间接相关和回查入口。资料保留，范围外只表示不进入当前任务。
2. **孤立句常常不够。** 证据单元应是核心句和必要的上下文，允许多个段落、表格标题/脚注共同支持一个结论。
3. **实体共现不是知识关系。** 还要判断实体分别属于哪个人群、研究组、干预、终点和结论，不能将同段出现的基因和药物自动连成治疗关系。
4. **实体类型不等于标准身份。** “这是药物”与“它对应哪个药物 ID”是两项任务；基因、蛋白、具体变异、变异类别也不能互换。
5. **结构正确不等于语义正确。** JSON 合法、引句真实存在，仍可能发生否定反转、错配试验组、扩大癌种范围或错误分级。
6. **关卡越多不自动越可靠。** 若五个硬筛环节每次仅保留进入该环节的真实目标的 95%，最终只保留约 77%（0.95^5）。这是条件保留率的示意，不是当前实测。

现有 Qwen3-1.7B 的历史 20 篇开发试验中，v1 与暂定范围参考一致为 6/20，v3 规则为 19/20；v2 大量失败来自输出结构。它说明需要保留规则基线、分开统计协议失败和语义错误，不能推导出所有小模型均不适用。参考不是人工金标准，历史样本也不是本轮“前 20 篇”。详见[实测记录](literature-model-pilot.md)。

小模型提出参考未列出的新证据时，由 Astra 回到原文复核“支持、不支持、证据不足”，记录原始提议、支持跨度、条件、修订原因及评审身份。确认遗漏后生成参考 v2，保留 v1 和原成绩，并以同一新版参考重算所有方法；不只给提出新证据的方法加分。Astra 能修订参考，但模型之间一致仍不证明语义正确。文献级摘要参考不能用于给全文证据召回评分。

## 4. 分层处理契约

这些是逻辑步骤，不要求每步部署一个模型、进行一次独立调用或阻塞等待人工确认。

| 阶段 | 输入和主要输出 | 推荐执行方式 | 不能静默忽略的问题 |
| --- | --- | --- | --- |
| S0 资料检查 | 来源版本、标题/摘要/全文、语言、发表状态、可解析范围 | 现有元数据和解析规则优先 | 缺全文、错配全文、撤稿/更正关系、解析失败必须单列 |
| S1 文献路由 | 肿瘤相关性、实体/血液/混合/未细分、研究对象、知识主题 | 现有规则 + 小模型分类对照 | 背景提及不是研究对象；良性/癌前、非肿瘤、信息不足分别保留 |
| S2 证据定位 | 核心句、段落上下文、章节角色、关联表格/脚注、证据用途 | 章节/术语规则宽召回 + 小模型相关性判断 | 保留否定、对照、结果与限制；不能只取含药物名的句子 |
| S3 实体识别 | 原文跨度、实体类型及其文中角色 | 批量 NER/跨度抽取，联合类型判定 | 重叠实体、缩写、跨句指代、基因与变异的区别 |
| S4 实体规范化 | 原文 mention → 标准命名空间、ID、版本、候选和匹配状态 | 字典/别名候选 + 上下文消歧 + ID 实存检查 | 不确定保留原文；不从字符串相似直接声明等价或让模型编 ID |
| S5 证据组装 | 结论、关系方向、人群、分子条件、干预/对照、结果、局限 | 关系模型或结构化抽取模型；疑难项补查上下文 | AND/OR/NOT、组别、时间点、否定、来源研究与背景转述 |
| S6 结构和语义核验 | 字段支持、关系配对、缺项、冲突、通过/不支持/证据不足 | 确定性检查 + 与抽取分开的 AI 核验 | 引句命中不等于结论受支持；相同模型两次回答不保证错误独立 |
| S7 保存与兼容预览 | 版本化候选/证据、相似知识、目标字段映射与缺项 | 关系主库和离线转换 | 重复、撤回、更新历史、来源丢失和有损映射 |

S1 至少拆开三个轴：相关性（直接/间接/无关/不明）、疾病范围（实体/血液/混合/泛癌未细分/良性或癌前/不适用/不明）、处理用途（治疗/诊断/预后/机制等多标签）。人体、动物、细胞和混合研究另存；前临床不等于无用，但不能变成人体治疗结论。分类轴允许独立未知，不强行补齐全部字段。

S2 以证据召回为重点，S5/S6 以结论正确性为重点。方法、人群定义、研究组名称可能远离结果句，必要时回查整篇。原文只给出关联时不能升级为因果；“未见显著获益”不自动等于耐药；“未检测”不等于阴性。

首 20 篇先做路由影子评测：逐篇核对被分到范围外、无证据和待判定的材料，不能只核对通过筛选者。稳定后再用抽样复查控制大批量漏检。

## 5. 知识结构：以独立结论为中心

“原型”在本方案中明确分为实体类型、本体/标准 ID、知识模板三层，分别回答是什么、具体是谁、参与什么结论。

建议的独立数据契约如下。它是待验证设计，不代表已经新增模型或 migration：

| 对象 | 需要保存的语义 |
| --- | --- |
| DocumentVersion / EvidenceSpan | 不可变资料和解析版本、原文跨度/页码/表格位置、精确引句、许可、来源类型 |
| EntityMention / EntityLink | 原文出现形式和位置、类型、标准 ID/命名空间/版本、歧义、链接依据 |
| Study / StudyArm | 研究身份、设计、对象、样本量、试验组/对照组及其条件 |
| Population / MolecularCondition | 癌种/亚型、分期/线次/既往治疗，具体变异或变异类别、检测条件、AND/OR/NOT |
| Intervention / OutcomeObservation | 单药/联合/顺序方案、比较关系、终点、数值/单位、分母、时间点和置信区间 |
| EvidenceConclusion | 类型、原文陈述、规范化陈述、关系方向、否定/不确定性、适用条件和引用集合 |
| KnowledgeAssertion | 后续按同一问题组织多条支持或冲突证据；不抹平来源差异，不自动生成共识 |
| ExtractionRun / ReviewRecord | 输入与 schema/模型/提示词版本、执行状态、核验结果、抽查、撤回和重新处理记录 |

核心要求：药物、癌种范围、分子条件必须关联到各自结论，不能放在整篇文章的无序列表里再进行笛卡尔组合。不同组别、时间点、来源和终点的数值不能串用。

每个关键字段附带支持它的 EvidenceSpan，不能只给整条记录挂一段宽泛引文。允许一个结论关联多个跨度；保留当前单段引用接口的兼容入口，扩展通过新版本契约实施。

空值还需有原因：`not_reported`、`unresolved`、`not_processed`、`not_applicable`、`conflicting` 等状态分开。`not_reported` 只限实际检查过的输入范围；解析失败不能记为未报告。模型自信度、证据临床等级、来源原始推荐等级和发布状态分别保存。

原始研究结果、综述转述和指南推荐使用不同知识模板。综述的参考文献不能自动算作已核读原始研究；同一试验的多篇报道保留文章级出处和研究级关联，避免当作多个独立试验重复计数。

## 7. 模型分工与成本控制

- 分类、候选段落和实体跨度适合比较规则、轻量编码器或专用抽取模型、小型指令模型。实体边界和类型可联合输出，不为每个词单独调用生成模型。
- GLiNER2 可作为分类/实体/浅层结构抽取候选，现有 Qwen3-1.7B 可保留为历史对照；哪一种进入各环节由新试验决定。预训练的生物医学编码器不等于现成分类器，任务微调需要可靠标注。
- 规范化先查字典和别名，再消歧和验证 ID。涉及多组别、跨句指代、数值条件的组装单独评测，不能因小模型分类合格就默认抽取也合格。
- 可以让多个任务共享一次编码/推理，分别保存结果和指标。通过阈值由独立数据验证；模型自报“0.95”不能直接当准确概率。
- 若小模型在某类任务不合格，可补上下文、暂存待处理，或评估更强模型；不为坚持全用小模型而强行发布。外部模型发送边界与资料许可另行确认，当前没有外发动作。
- 正式运行前固化 biomed 独立推理环境，不修改其他项目的依赖、驱动或 GPU 服务。记录首次加载、预热后耗时、每篇/每段调用次数、输入输出量、显存、失败重试与需补查比例。
- 沿用现有持久任务与断点机制；输入版本、步骤、模型、提示词、schema/config 共同确定执行身份。只重跑变化及受影响下游，不覆盖旧输出。
- 离线试验限制资源并在模型调用之外提交短数据库事务，避免再次与采集争用长写锁。采集限速不变，不新增全量抽取作业。

采用后训练的依据应是：标签定义已稳定、重复性语义错误已定位、可靠训练资料与独立测试资料已分开，并且改输入或修协议不足以解决。30 篇用于定位这些问题，不能一边用于调模型，一边证明模型泛化。优先学习“按本项目定义分类/定位/提取”，而不是先用所有原文做继续预训练；后者是否有必要需另设任务和对照。大模型可以产生候选标注，核验、争议和引用信息必须一同保留。

LoRA 冻结基础权重、学习少量适配参数，适合评估任务微调和后续客户侧交付，但不保证医学语义正确或推理更快。训练方案确定前需实测显存、上下文长度和批量；当前推理显存不等于训练所需显存。依据：[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-1.7B)、[PEFT LoRA 文档](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora)。

### 指标与验收

| 层级 | 必须报告的指标 | 优先定位的错误 |
| --- | --- | --- |
| 文献路由 | 各类召回/精确率、混淆、拒判和范围外数量 | 真正相关论文被排除、混合研究被错误单分 |
| 证据定位 | 参考证据跨度召回、候选精确率、每篇候选量 | 只找到结论而遗漏否定、方法或条件 |
| 实体识别/链接 | 边界与类型 F1、标准 ID 正确率、未解析比例 | 把不同实体错合并、基因与变异互换 |
| 关系与条件 | 完整关系及条件元组精确率/召回率、关键字段正确数 | 错癌种、错药物/变异、方向反转、研究组与数值错配 |
| 最终证据 | 原文支持、关键证据覆盖、引用定位、修正耗时 | 无依据结论、扩大适用范围、重复试验计数 |
| 运行和兼容 | 每环节耗时、恢复/重复执行、无损/受阻转换数 | 无结果被冒充无知识、丢来源、重复创建 |

所有指标同时报告分子/分母和拒判/覆盖率，按资料和标签分开；不能仅在模型成功输出的子集上报准确率。拒判是风险控制，不是正确抽取；因拒判未产出的参考证据仍计入端到端漏检/未覆盖。字段只在预先定义的适用范围内评分，关键条件另做整条证据是否完整正确的判断。

每层做两个对照：使用正确参考输入测该层能力；使用上一步实际输出测累计影响。最终端到端召回以原始 20 篇中的参考证据为分母，不能随着上游筛选缩小分母。另对照一次直接结构化抽取基线，检验拆分是否确实降低错误或成本。

小样本验收门槛：

1. 20 篇都有真实终态，成功、部分成功、等待资料、拒判和失败分别呈现；每条输出可回到对应版本原文。
2. 参考中的关键证据要么正确产生，要么能在核对中定位明确的遗漏原因；不能把不知道漏了什么描述为已完整处理。
3. 本批拟进入“已核验”输出中不接受错药物/变异/癌种、否定反转、跨人群泛化、伪造数字或来源等关键错误。发现后修复并验证受影响环节，保留失败记录。
4. 同时公开正确产出、漏检、拒判和修正数量。全部拒判不代表可用，所有格式校验通过也不代表语义合格。
5. 重跑不重复入库、不覆盖旧证据；不完整或有损导出明确阻塞；全程不写任何 tumor 生产项目。

这里“本批未出现关键错误”只是试验结果，不代表真实错误率为零。20 篇不足以建立稳定阈值、证明全癌种性能或生产适用性；后续按类别扩大独立测试，并报告不确定性。

| 步骤 | 交付物 | 下一步需要的依据 |
| --- | --- | --- |
| A 固定输入与标签规范 | 前 20 篇清单、实际全文状态、范围/实体/关系标注说明、兼容差距表 | 无悄悄换样本，范围与未知定义清楚 |

| C 证据定位和实体规范化 | 每篇核心句及上下文、实体候选与链接结果 | 关键条件未被截断，标准 ID 可核实 |

当前结论只限这套配置和这批开发样本：保留规则基线，Qwen 多标签配置暂不接管自动筛选。下一轮按以下顺序推进：

1. **分类诊断**：保留失败基线，先做“仅疾病范围”任务和解码/输出约束的单因素对照，检查是否为提示词、生成协议或环境兼容问题，再决定换模型或微调；不能直接据此次失败认定所有小模型不可行。
2. **规则缺口**：胆道 `biliary tract cancer` 别名、息肉/良性病变与背景癌史、胃癌与肠化生共同研究分别建立回归项；不覆盖 v3 历史输出。
3. **证据定位**：先补 JATS 章节路径和段落角色。抽查发现方法、背景、图表说明和书目引用都会命中；方法和脚注可能含必要条件，不能一律删除。优先验证胆道癌、乳腺混合转化研究、随机试验和撤稿通知，并同步核查未命中段落以查漏。
4. **证据级参考**：Astra 独立阅读选定全文，标注本研究结果、适用条件、否定和研究对象；模型新提议经原文裁决后版本化追加。完成这一层后才报告段落精确率/召回率，并比较专用跨度模型。
5. **后训练入口**：标签和任务稳定后，建立独立研究家族保留集，再评估监督 LoRA。当前 30 篇继续做开发案例，不用它们同时训练和证明效果。

## 11. 研究参考与适用限制

- [GLiNER2，EMNLP 2025](https://aclanthology.org/2025.emnlp-demos.10/)：同一编码器框架支持实体、分类和层次结构抽取，为共享模型而保留分任务输出提供依据；不是实体瘤领域质量保证。
- [CoRE，ACL 2026](https://aclanthology.org/2026.acl-long.1517/)：研究文档级生物医学关系提取中的轻量检测和疑难项再推理，提示需要跨句上下文；其 BioRED/CDR 结果不能等同本项目的全文临床证据验收。
- [From chaos to clarity，BMC Medical Research Methodology，2026](https://link.springer.com/article/10.1186/s12874-026-02847-8)：schema、词表和字段证据约束可用于可审计全文抽取。论文也明确缺少充分统计效力的完整金标准评估，且表图处理有限；因此不照搬其速度或正确率承诺。
- [CIViC Evidence Items](https://docs.civicdb.org/en/latest/model/evidence.html)：可参考来源、分子条件、疾病、治疗和独立证据陈述的组织方式。
- [GA4GH VA-Spec 1.0](https://va-spec.ga4gh.org/en/1.0/)：可参考 Statement、Evidence Line、Study Result 的语义分层；不意味着本项目已实现或通过标准兼容认证。

本方案中的模型分工、验收条件和版本策略是针对 biomed 的工程建议，并非上述论文已验证过的本项目结论。
