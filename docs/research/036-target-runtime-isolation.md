# 036 · 两条知识的目标运行路径隔离验证

时间：2026-11-12。用户确认知识提取不必强行划分 A/B/C/D，未知等级应保留；本次不推测等级，也不把观察结果强行标为敏感或耐药。两条候选和 Astra 原文参考来自 [035](035-entity-scope-closure.md)。

## 结论

两条知识**可以作为未分级的证据信息保存并在管理端检索**：在使用 tumor_api 同一镜像和只读源码的隔离环境中，目标真实 serializer 均接受原载荷，并在全新内存 SQLite 中实际保存、读取和搜索成功。创建结果均为待处理、锁定、未启用；相同载荷再次创建时被目标的精确重复检查拒绝。这是隔离库实测，尚未导入生产，也不是目标当前完整 PostgreSQL 部署验收。

两条知识**尚不能安全地自动用于患者治疗报告**：模拟目标记录已审核且启用后，目标可依据对应主癌种和变异匹配两条证据，但现有治疗报告路径遇到未分级 `-` 会抛出错误，并不会依据描述文字自动约束一线、二线或卵巢癌亚型。当前目标的 `solid_treatment` 开关在 2026-11-12 15:32（北京时间）只读查询为 `combined`。因此，如果将未分级治疗证据直接审核启用并命中对应样本，该报告路径存在报错风险。**本次没有修改或启用生产记录，现有生产报告未受本次测试影响。**

| 检查项目 | 肺癌：EGFR L861Q | 卵巢癌：KRAS G12C |
| --- | --- | --- |
| 当前目标药物与主癌种 ID | 达可替尼、非小细胞肺癌 ID 存在，名称与冻结快照一致 | Sotorasib、卵巢癌 ID 存在，名称与冻结快照一致 |
| 未分级载荷的真实目标校验、隔离保存与管理搜索 | 通过 | 通过 |
| 模拟审核启用后，正确主癌种与变异 | 命中；依赖正确的蛋白变异注释生成精确自身事实 | 命中；目标位点库存在精确 G12C 索引 |
| 不同基因、不同替换、不同主癌种、缺失蛋白变化 | 均未命中 | 均未命中 |
| 未分级治疗报告 | 报错：要求有效等级 | 报错：要求有效等级 |
| 文献条件的目标自动约束 | 一线、二线模拟样本都命中 | 低级别浆液性及其他卵巢亚型模拟样本都命中 |

错误药物和癌种 ID 都被目标实际 serializer 拒绝。当前目标中按本次两组**精确字面基因位点、药物和主癌种**进行有限只读查询，未发现同核心结论；该查询不覆盖别名、复合键、其他知识库和全部语义近义事实，不能当作全库去重证明。

## 两个位点为何表现不同

目标位点库的肺癌条目是 `index=L861`、`variant=L861Q`。目标详情序列化器按照 `index` 解析，隔离测试中的 L861Q 精确位点状态为未解析；但有完整且基因一致的蛋白注释 `p.L861Q` 时，目标会从合成 SNV 自身生成精确事实，因此样本匹配可以命中。缺失蛋白变化时，本例没有命中。详情显示未解析与样本匹配命中不矛盾，但两者不能互相替代。

KRAS 的现有位点条目 `index=G12C`、`variant=G12C`，目标详情解析及模拟样本匹配都命中。额外构造的异常输入中，样本基因字段为 KRAS、注释字符串的基因为 OTHER、蛋白变化仍为 G12C；因为现有位点库检索仍按样本基因和蛋白变化返回 G12C，这个合成输入仍命中。没有查询任何真实患者数据，也没有证据说明实际数据中存在该问题；它说明对自动匹配还需要处理输入基因和转录本注释冲突。

主癌种匹配还使用目标的中文名称。模拟病例写“非小细胞肺癌”时肺癌知识命中，写“肺癌”时不命中；这不代表真实患者使用哪种名称，只说明目标这条路径不会自动递归或归并主癌种名称。实验中的转录本和核苷酸标注为合成字符串，不证明真实不同转录本或基因组变异之间的等价性。

## 必要条件如何保留和核对

原文的一线治疗、疾病亚型、病例既往治疗与用药方案，已留在目标的证据描述和 biomed 配套记录中；目标按基因位点和主癌种查询时不会读取这些自由文本作为患者条件。目标 `evidence_source` 保存 PMID/DOI 及 biomed 记录标识，**文章级来源可保留；段落精确定位仍依赖 biomed 配套记录**，不能把目标描述中的 `P5` 等别名当作目标库独立可解析的段落链接。

本次在 biomed 做了一个未接后台的条件对照原型：将来源明确的一线治疗和低级别浆液性亚型分别作为本次两条知识的研究范围，接收已标准化的上下文，输出“与报道范围一致／不同／缺少信息”。不同或未知都**不隐藏知识**，也不自动判断患者是否适用；剂量、口服频率、既往治疗和分期保留为案例或治疗描述，不凭空变成患者入选条件。以下是合成上下文的结果：

| 原文范围 | 合成上下文 | 目标自身 | biomed 对照原型 |
| --- | --- | --- | --- |
| 一线治疗 | 一线 | 命中 | 与报道范围一致 |
| 一线治疗 | 二线 | 仍命中 | 与报道范围不同 |
| 一线治疗 | 未提供 | 目标不检查 | 范围信息未知，仍可检索 |
| 低级别浆液性卵巢癌 | 低级别浆液性 | 命中 | 与报道范围一致 |
| 低级别浆液性卵巢癌 | 其他已知亚型 | 仍命中 | 与报道范围不同 |
| 低级别浆液性卵巢癌 | 未提供 | 目标不检查 | 范围信息未知，仍可检索 |

这两个比较条件是根据已有事实与原文为实验明确指定的；尚未证明其他文献中的条件能自动、完整地提取和标准化，也没有与目标患者数据或报告路径对接。条件比较不是患者入选判断或治疗建议。原型在目标代码之外运行，不替代目标的医疗规则。

## 验证边界和下一步

目标 ID 与位点信息只读取了这两条涉及的字典及有限匹配数量；只读事务、超时和未访问患者数据均有记录。真实保存与目标查询发生在**无网络、只读源码、全新 SQLite `:memory:`**，表仅在空的临时库创建一次，没有运行迁移或操作已有表；隔离库的证据 UUID 都是临时值。对照另以禁止任何数据库连接的模式运行，得到一致的条件匹配结果。目标源码和运行镜像的哈希已保存，当前证据匹配服务与 11 月 1 日冻结版本的哈希不同，本次结果针对当前实测代码。

目前适合的使用方向是保留未分级知识及出处、提供知识检索和原文查看；不要把未分级改成虚构等级。要支持目标治疗报告，还需在**不修改本次生产项目**的前提下，设计目标消费者如何处理未分级知识、未知药效及一线／亚型等范围，并为已有报告提供清晰的跳过或信息展示行为。需要消费这些条件时，还要取得可信的标准化上下文；缺失时保持未知。后续再用更多新文章验证自动条件抽取，确认行为与运行开销后再讨论接入。
