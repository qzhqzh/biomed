## 实际使用的模型与资源

先复用本机 `/data/models/Qwen3-1.7B`，避免首次就下载 4B 权重。权重、配置、tokenizer 等 9 个文件与 [Qwen 官方版本](https://huggingface.co/Qwen/Qwen3-1.7B/tree/70d244cc86ccca08cf5af4e1e306ecf908b1ad5e) 校验一致；证据在 `var/library/decisions/qwen3-official-verification.json`。核对只下载了小型公开文件清单，没有下载权重，也没有向外部模型发送文献。

- 使用物理 GPU 3（第四张 RTX 2080 Ti），FP16、eager attention、2 个 CPU 线程；显存分配限制为该卡的 50%，不启用多卡。
- 本机默认 PyTorch 2.12.1+cu130 与现用驱动不兼容。本轮复用已有兼容的 PyTorch 2.5.1+cu124 / Transformers 4.57.3，真实 GPU FP16 运算及推理通过，没有更新全局驱动或改动现用 Web 依赖。
- 实验解释器在 `var/runtime/decision-venv/bin/python`。它通过项目内 `.pth` **只读复用** `/data/05_workspace/Voice/old_voice/.venv/lib/python3.12/site-packages` 的现有运行库；这是临时实验依赖，尚不是独立固化的长期推理服务。正式持续运行前需在项目独立环境中固定依赖，不能依赖清理旧目录后仍可运行。
- 模型仅作本地推理，非训练。正式证据抽取 / 审核的 `CURATION_MODEL_BACKEND` 仍未配置，保留 `waiting_configuration`。

## 两版真实试验

从原 60 篇开发集的五个抽样层各固定选 4 篇，共 **20 篇**。不把参考标签或规则结果发送给模型。两版使用相同 20 篇，第二版根据第一版开发错误修改提示词，因此两版均为开发试验，不能当作独立测试或总体准确率。参考仍是助手暂定核读标签，尚无人工作为金标准确认；先前单篇兼容性试推理另计，不纳入下表。

| 方法 | 结构及引句校验通过 | 端到端范围与暂定参考一致 | 推理耗时 / 平均每篇 | 峰值显存分配 |
| --- | ---: | ---: | ---: | ---: |
| v3 规则（同 20 篇） | 不适用 | 19 / 20 | 本轮未单独测速 | 不需要 GPU |
| 模型 v1：范围与多标签一起输出 | 17 / 20 | 6 / 20；有效输出内 6 / 17 | 201.60 秒 / 10.08 秒 | 3,687.4 MiB |
| 模型 v2：只判断对象与范围，补充类型映射 | 1 / 20 | 0 / 20 | 155.51 秒 / 7.78 秒 | 3,587.4 MiB |

模型加载分别约 8.20 秒、9.99 秒，单列于推理时间。模型 v1 的已完成批次再次执行时复用了原 20 份结果，没有重新加载模型或重复推理。

这些数字没有证明模型可替代规则。v1 把 16 篇归为 `oncology_unspecified`，存在明确胃癌、垂体癌仍被视作类型不明的漏判；还出现部位标签的引句虽然真实存在、语义却不支持该部位的情况。另有 2 条非法标签 / 角色、1 条不合格引句被拦截。

v2 有 17 条不符合所要求对象结构（常见缺少 `labels`），另有 2 条含多余 JSON / 文本；唯一通过结构检查的结果也未与参考一致。**v2 的 0/20 是包含输出失败的端到端结果，不应解读为对全部原始文字判断做了独立语义评分。** 没有事后补空字段、替换非法标签或丢弃失败样本来抬高成绩。

部位、组织学、研究类型等轴尚无参考标签，本轮不报告它们的准确率。规则 19/20 也来自开发材料，并不代表全库正确率。按 v1 当前短样本平均耗时机械外推，每千篇约 2.8 小时，仅说明此配置不宜直接用于百万篇全量分类；真实吞吐仍受文本长度、批处理和硬件影响。

## 实现、保存与恢复

- `scripts/classify_literature.py`：仅加载本地 safetensors，禁用联网与远程代码；固定输入、模型文件哈希、提示词、推理参数和代码哈希。原始输入与输出按篇保存，单批最长时间、输入长度和输出长度有上限；不静默截断摘要。
- 每篇输出写成独立原子文件，运行目录加锁。相同输入 / 配置 / 代码可复用已完成结果；失败输出也保留，不自动反复尝试。输入、模型或提示词改变必须使用新目录。创建运行目录中的 `STOP` 文件可在当前篇结束后暂停。
- `apps/curation/decision.py`：检查标签范围、字段结构和原文精确字符偏移；引句存在只是结构门槛，不代替语义核对。
- `literature_import_decisions`：重新核对不可变原始元数据及 PMID，再在短事务内追加模型候选。v1 的 17 条、v2 的 1 条分别保存为 `experimental / unreviewed`；3 条和 19 条失败输出留在运行文件中，不伪装成有效分类。新旧结果都保留，没有发布证据。
- 默认分类选择明确排除实验模型的自动接管，即使某次实验覆盖整个批次，也不会因时间较新而取代规则。当前页面默认仍为完整的 v3 规则。模型比较目前通过本地 CSV / JSON 查看，尚未新增独立模型比较页面。

后续执行示例（使用新目录，不覆盖本轮文件）：

```bash

  var/runtime/decision-venv/bin/python scripts/classify_literature.py \
  var/library/decisions/qwen3-1.7b-pilot-v1/selected-inputs.json \

# 完整批次结束后，核对并追加候选；不替换规则或启动证据发布。
docker compose exec -T web python manage.py literature_import_decisions \
  /app/library/decisions/<new-run>/run
```

## 下一步选择

继续把规则、模型预测、人工抽查和正式证据审核分开。下一组模型对照优先考虑支持 schema 分类的 GLiNER2，以及 4B 指令模型用于语义疑难项；先测格式可靠性、范围 / 提及角色、速度和资源，再决定路由。当前 1.7B 的这两版配置不推广到全库，也不据此生成训练答案。扩大采集可沿用现有断点和限速，后续仍按有限批次记录资源使用；模型训练继续留在基线和可信评测集建立之后。
