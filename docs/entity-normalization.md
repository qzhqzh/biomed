# 每批知识共用的实体归一

2026-11-06：此前35个是某一批的未匹配名称，不能成为维护清单。当前以 `scripts/normalize_knowledge_entities.py` 和 `apps/curation/entity_normalization.py` 为共同入口，接入 `scripts/run_literature_batch.py`。输入任意 `knowledge-candidates-v1` 批次，不包含指定 PMID、名称列表或固定数量的分支。

## 后续新名称如何处理

1. **复用身份**：先查 biomed 中已确认的标准实体、别名和本文缩写规则，完整标准名唯一命中也直接处理。
2. **自动判断**：其余名称从现有 RxNorm、MONDO、ChEMBL、OncoTree 和本地实体库取候选，由现有 Qwen3.5-9B 结合本篇原文选身份、识别新实体或纠正类型。无人工逐项批准步骤。
3. **自动扩展**：模型明确识别且原文可定位的新药或疾病，自动生成本地稳定ID和规则；有标准ID则保留，没有也可按原文名称登记，不虚构外部ID。未知疾病层级可以暂留未分层，不阻断身份保存。
4. **持续复用**：`--import-to-local` 将规则和实体保存到 biomed，再保存知识。下一批自动读取届时的本地库；全名别名直接复用，缩写和带条件的映射保留文章范围。新实体不必修改代码，也不重新拉 tumor_api 底库。
5. **适配目标**：已确认的具体药物若目标快照缺项，继续生成自动查重、新增和ID回填操作。当前只在隔离预览库执行，生产连接未接入；癌种目标缺项、分子条件和目标字段限制仍单独展示，不能假称已导入。

## 必要的通用约束

- 候选检索忽略 `-`、`nan` 等占位名，完整词匹配避免把短缩写误匹配到普通单词内部；标准别名、本文缩写定义和本地已确认别名优先，模糊候选须由模型判断。
- 文章内其他片段可补足缩写定义，但必须属于同一原文版本与文件哈希。原始知识、条件、文章和段落出处不改写。
- 原文明确列出多个已知药物的方案，不能归成其中一个单药；纯分子限定不能作为癌种。类型纠正另存，目标导出显示 `not_target_entity`，不把它当成新药。
- 未知短代号、`compound 7` 一类文章内临时名称不能直接创建全局身份；须有原文完整名称、稳定化合物代码或已确认的标准身份，避免不同论文中的同名临时代号误合并。
- 模型不能创造候选ID，新增名必须能在原文找到。段落定位由脚本负责：模型缩短或改写了引文时，使用包含对应名称的真实原文片段并记录调整，不把模型文字冒充原文。身份已经明确而主癌种层级建议无效时，只舍弃该层级建议，不否决正确的身份匹配，也不擅改既有分类。
- 完整字段仅缺JSON末尾一个右括号时可由脚本补齐，保留原始输出和修复说明；不会补写缺失字段或值。结构或来源校验拒绝的模型决定最多带具体原因自动纠正一次，再失败即单独保留，不反复调用到“通过”为止。
- 明确信息不足、既有冲突、来源问题独立记录，其他实体继续处理；不把所有不确定名称强行新增。重试沿用有效模型断点，输入、候选集合、提示词和模型版本一致才复用。

模型缓存保存原始输入、原始输出和配置哈希，结果按内容版本追加。它是推理复用，不是人工金标准，也不把“完成归一”解释为知识语义已全面核验。

## 运行入口

正式批次继续用原来的 `scripts/run_literature_batch.py ... --import-to-local`；完整执行和全文补齐分支已接通归一。未指定 `--registry` 时冻结本批开始时的 biomed 小型实体库快照。`--deliver-only` 只运行规则并复用已完成模型结果，不临时启动 GPU。

已有知识可单独执行，不重跑上游抽取：

```bash
.venv/bin/python -B scripts/normalize_knowledge_entities.py \
  --bundle var/experiments/RUN/knowledge.json \
  --registry var/experiments/RUN/registry-input.json \
  --output var/experiments/RUN/entity-normalization \
  --import-to-local
```

去掉 `--import-to-local` 仅生成可检查的补丁与更新后的快照；加 `--rules-only` 不启动模型。输出的 `registry-snapshot.json` 可直接交给目标适配脚本。后续新批次应读取当前 biomed 库，旧快照仅用于实验重放。

实验与断点位于 `var/experiments/` 的 appdata 兼容入口，模型缓存目录为 `entity-normalization-cache-v1/`，权重继续复用 `/data/models/Qwen3.5-9B`。没有新增依赖、下载模型或修改 tumor_api。
